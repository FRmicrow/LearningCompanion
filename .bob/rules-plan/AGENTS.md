# Plan Mode Architectural Constraints (Non-Obvious Only)

- **Capture pipeline is synchronous after upsert**: `CaptureProcessorService.process(text:)` calls `repository.upsert` synchronously (GRDB `dbQueue.write` blocks), then awaits translation. Any new pipeline step that performs I/O must be `async` and follow the existing `await` chain.
- **No direct DB access outside repository**: all GRDB reads/writes go through `VocabularyEntryRepository`. `VocabularyListView` has its own `ValueObservation` but uses `repository.dbQueue` — do not expose `dbQueue` to new services.
- **Timer architecture constraint**: `ClipboardMonitorService` uses a single `DispatchSourceTimer` that runs permanently (even during pause). Any new "pause-like" feature must suppress the delegate call rather than cancel and recreate the timer.
- **Translation fallback is always LibreTranslate** (even on macOS 15+) because Apple's `Translation` framework originally required a view context. This was worked around by `TranslationSessionHost` — an invisible off-screen `NSWindow` that keeps a `TranslationSession` alive from launch. Any new translation pathway must use the same host, not create its own session.
- **`AppDelegate` is the composition root** — all service wiring happens in `applicationDidFinishLaunching`. Services do not reference each other except through the pipeline chain defined there. The production LibreTranslate URL (`http://localhost:5001/translate`) is also set here, not in `TranslationService` itself.
- **Two connectivity event sources**: `NWPathMonitor` (for retry-on-reconnect) and `URLError` silently caught in `translate(entry:)`. Any new offline feature must use `NWPathMonitor`, not polling or reachability flags.
- **GRDB migrations are forward-only** (by GRDB's `DatabaseMigrator` design). Schema changes must be additive (`ALTER TABLE … ADD COLUMN`); destructive changes are not supported without a new DB file. Currently at `"v2"` — next migration must be `"v3"`.
- **Specs are contracts**: `specs/001/`–`specs/004/` each contain a `contracts/` directory with authoritative service API definitions covering method signatures, threading guarantees, and error contracts. Deviating from any contract breaks stated behaviour.
